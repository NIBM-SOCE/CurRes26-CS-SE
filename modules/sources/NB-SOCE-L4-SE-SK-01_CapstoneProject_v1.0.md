## 2. Module Purpose and Aims

### The COMMON FRAME (master-issued, reproduced VERBATIM)

> **Capstone Project (5 credits, Level 4, Profile C - 250 notional hours):** Project briefings and methods input 15; Supervision meetings 21; Laboratory / build access (supervised) 39; Presentation, demonstration and viva 9; Independent project work 166. Assessment components: CW project artefact with build log (take-home, supervised access; oral vehicle: Presentation at demonstration) and a final report with **Viva-defence** (mandatory oral vehicle). No examination. Weightings proposed by the thread and confirmed at sign-off. The artefact is the second designed public-portfolio vehicle (with Creative Project) and is TVEC-orientable evidence.

*The frame above is fixed across all four pathways; pathway flavour lives in briefs, domains and supervision, never in the frame.*

### Pathway Purpose (SE flavour: briefs, domains, supervision)

The Capstone is the integrative, output-oriented project of the CS(SE) pathway: students plan, build, evaluate and defend a substantial software outcome that draws together the Year 2 applied spine. Project briefs are SE-domain briefs - application builds across the enterprise, web and cloud, mobile, connected-device and AI-enabled territories of the pathway; electronics and IoT capstone themes are properly resourced through the DELD laboratory kit (V2) - upgraded from aspiration to supported theme. Supervision is by SE domain staff. The artefact is the pathway's second designed public-portfolio vehicle (with Creative Project), a documented value point for graduate positioning. The scope limit is quoted below: the degree-level independent research depth belongs to the Coventry destination.

### Specification Boundary (from the record set - QUOTED, never edited)

> **Covers:** an integrative, output-oriented SE pathway project; methods input; supervision; demonstration and viva.
>
> **Does NOT cover:** the degree-level independent research depth of NB6020CEM.
>
> *Boundary changes are change requests against Master Decisions, not descriptor edits.*

## 4. Skills Programme (Profile C structure)

### Briefings and Methods Input (15 hours, five 3-hour blocks)

| Block | Theme |
|---|---|
| B1 | Project scoping and the proposal: brief selection, scope definition, plan |
| B2 | Methods for integrative builds: applying the taught spine to a single outcome |
| B3 | Build discipline: version control, incremental delivery, the build log |
| B4 | Evaluating the outcome: testing and evaluation of project results |
| B5 | Portfolio, demonstration and viva preparation |

### Supervision Pattern (21 hours)

Scheduled supervision meetings across the project period with the assigned SE domain supervisor; individual assessment throughout, with the meeting cadence (weekly or fortnightly pattern) set at teaching-plan stage. Supervision records feed the assessment evidence set.

### Laboratory / Build Access (39 hours, supervised)

Supervised build access in the pathway laboratories; the DELD-resourced kit is available for electronics and IoT project themes. Supervised access is the setting attribute of the artefact component in Section 5.

### Presentation, Demonstration and Viva (9 hours)

A demonstration event at which the artefact is presented publicly, and an individual viva on the final report.

### Independent Project Work (166 hours)

The largest share of the profile, per the invariant; the independent build, evaluation and writing effort.

## 5. Assessment

Components per the common frame; weightings proposed here per the frame's rule and confirmed at sign-off.

| Component code | Task | Attributes | ILOs | Weight |
|---|---|---|---|---|
| CW-I-Home | Project artefact with build log: the integrative build and its individually maintained build log | Individual; take-home (supervised laboratory access); graded; oral vehicle: Presentation (at demonstration) | LO1, LO2 | 60 |
| CW-I-Home | Final report with Viva-defence: the project report defended at individual viva | Individual; take-home; graded; oral vehicle: Viva-defence | LO2, LO3 | 40 |

No examination is carried, per the frame. Both components are graded; no pass-fail component is proposed - the TVEC competency-evidence orientation is met by the graded artefact set (artefact, build log, report, viva record), which is auditable evidence regardless of grading mode. Weights sum to 100. Reassessment is by failed component. Academic-integrity and generative-AI expectations follow School policy; the build log, supervision records and Viva-defence are the authorship evidence.
