## 2. Module Purpose and Aims

The module builds design method for the CS(SE) vertical: the user-centred design process, user research and the derivation of interface requirements, interaction design, prototyping from low to high fidelity, and introductory usability evaluation. It exists because the HND profile otherwise supplies prototyping maturity - through Creative Project - but no HCI method; this module supplies the method, so that the Level 5 destination receives students who can research users, design interactions and evaluate usability, not only build. The scope limit is deliberate and quoted below: this is design method, distinct from web and mobile implementation technology, and advanced usability laboratory technique belongs to the Coventry destination.

### Specification Boundary (from the record set - QUOTED, never edited)

> **Covers:** user-centred design process; user research and requirements for interfaces; interaction design; prototyping method (lo- to hi-fidelity); introductory usability evaluation. This is design method, deliberately distinct from web and mobile technology.
>
> **Does NOT cover:** web or mobile implementation technology (Web and Cloud Application Development; Mobile Application Development I); advanced usability laboratory technique (NB5001CEM at Coventry).
>
> *Boundary changes are change requests against Master Decisions, not descriptor edits.*

## 4. Curriculum and Delivery

### Indicative Syllabus

| Unit | Content | Lecture hours |
|---|---|---|
| U1 | The user-centred design process: principles; process models; where design method sits in the development lifecycle | 6 |
| U2 | User research: interview and observation methods; personas and scenarios; deriving interface requirements from findings | 9 |
| U3 | Interaction design: interaction patterns; information architecture; navigation and task flow | 9 |
| U4 | Prototyping method: low-fidelity sketching and wireframes; high-fidelity interactive prototypes; iterating on feedback | 12 |
| U5 | Introductory usability evaluation: heuristic evaluation; planning and running simple user tests; analysing and reporting findings | 12 |
| | **Total lecture hours** | **48** |

Sessions run as 3-hour blocks (16 sessions); the practical allocation runs studio-style, carrying one design case from research through prototype to evaluation across U2-U5. Prototyping tooling is design-tool based, not implementation technology, holding the boundary.

## 5. Assessment

Components per the Assessment Component Taxonomy; weightings confirmed at specification sign-off.

| Component code | Task | Attributes | ILOs | Weight |
|---|---|---|---|---|
| CW-I-Home | Design portfolio: user-research summary with derived requirements, an iterated prototype (low to high fidelity), and a usability evaluation report with design recommendations | Individual; take-home; graded; oral vehicle: Presentation | LO1, LO2, LO3 | 70 |
| CW-I-Class | Supervised design exercise under open-resource conditions: a timed heuristic evaluation of a supplied interface | Individual; in-class; graded; oral vehicle: None | LO3 | 30 |

No examination is carried by design: the assessed capability is design method demonstrated through the researched, prototyped and evaluated portfolio; the presentation of the portfolio and the supervised in-class evaluation anchor integrity and authorship. Weights sum to 100. Reassessment is by failed component. Academic-integrity and generative-AI expectations follow School policy.
